# BnTradingPro — Binance 现货专业手动交易终端（Rust + egui）

## 需求确认
- **市场**：现货 Spot（MVP，架构预留合约扩展）
- **功能**：专业手动交易终端 — 行情看板（实时价格/深度/K线/成交流）、账户余额、手动下单（市价/限价/止损限价/止盈限价）、订单管理与撤单、成交历史
- **行情**：WebSocket 实时推送
- **密钥**：主密码加密存储（Argon2id + AES-256-GCM）
- **界面语言**：中文（内嵌/加载 CJK 字体）
- **安全性**：内置 Testnet（testnet.binance.vision）切换开关，正式盘界面带醒目标识

## 技术栈
| 用途 | 依赖 |
|---|---|
| GUI | `eframe`/`egui`（实现时 `cargo add` 取最新稳定版） |
| 异步运行时 | `tokio`（rt-multi-thread + macros） |
| REST | `reqwest`（json + rustls-tls，避免 Windows OpenSSL 问题） |
| WebSocket | `tokio-tungstenite`（rustls） |
| 签名 | `hmac` + `sha2` + `hex` |
| 精确数值 | `rust_decimal`（价格/数量/金额绝不用 f64） |
| 加密存储 | `argon2`（KDF）+ `aes-gcm` + `zeroize` + `rand` |
| 序列化 | `serde` + `serde_json`，时间 `chrono` |
| 并发容器 | `parking_lot`，通道 `tokio::sync::mpsc` |
| 错误/日志 | `thiserror` + `anyhow`，`tracing` + `tracing-subscriber` |

## 架构设计

egui 是立即模式 UI，UI 线程绝不阻塞网络。核心是"UI 线程 + 后台 tokio 引擎"的命令/快照模型：

```
┌────────────────────────────────────────────┐
│ UI 线程（eframe，~60fps）                    │
│  读取 Arc<RwLock<快照>> 渲染                  │
│  用户操作 → mpsc 发送 Command                 │
└─────────────┬──────────────────────────────┘
              │ Command（下单/撤单/订阅/查询…）
┌─────────────▼──────────────────────────────┐
│ tokio 后台引擎（独立线程池）                   │
│  ├─ command_task  : REST 请求执行者           │
│  ├─ market_ws     : 组合行情流，指数退避自动重连  │
│  ├─ user_ws       : listenKey 用户数据流       │
│  │                  (executionReport/余额推送，│
│  │                   每30分钟 keepalive)      │
│  └─ keepalive/限速 : 服务器时间偏移同步、       │
│                      X-MBX-USED-WEIGHT 限速   │
└────────────────────────────────────────────┘
   写入共享快照（ticker/depth/klines/balances/orders/trades）
```

关键 API 设计（现货）：
- REST：`/api/v3/time`（时间偏移）、`exchangeInfo`（过滤器缓存）、`ticker/24hr`、`depth`、`klines`、`account`、`order`(POST/GET/DELETE)、`openOrders`、`myTrades`、`allOrders`、`userDataStream`(POST/PUT/DELETE)
- WS 组合流：`<symbol>@ticker`、`@depth20@100ms`（部分深度快照，避免实现困难的增量深度同步，对手动终端足够且更稳）、`@kline_<interval>`、`@aggTrade`、`<listenKey>`（订单/余额实时推送）
- 环境切换：生产 `api.binance.com` / `stream.binance.com:9443`，Testnet `testnet.binance.vision`，base URL 可在设置中覆盖

## 关键工程点
1. **签名**：`HMAC-SHA256(queryString, secret)` hex 编码，附 `timestamp`(+服务器偏移) 与 `recvWindow`
2. **数值量化**：下单前按过滤器将价格取整到 tickSize、数量取整到 stepSize、校验 minNotional，UI 实时显示量化后值与预估成交额
3. **下单确认弹窗**：展示方向/类型/价格/数量/预估金额，二次确认（专业 + 防误操作）
4. **WS 稳定性**：断线指数退避重连 + 全量重订阅；listenKey 30 分钟保活、失效自动重建；UI 显示连接状态指示灯
5. **密钥安全**：Argon2id 派生密钥，AES-256-GCM 加密落盘，内存中 Secret 用 zeroize，日志全量脱敏
6. **测试网水印**：Testnet 模式窗口标题+界面角标显示 "TESTNET"；实盘显示红色 "实盘" 徽标

## 实施步骤
1. **脚手架**：`cargo init`、依赖、.gitignore、git init、字体与主题、主窗口框架与页签导航
2. **安全模块**：主密码设置/解锁流程、加密 vault 读写（含单元测试：加解密回环）
3. **REST 客户端**：时间同步、签名、exchangeInfo/account/openOrders 拉取、Binance 错误码 → 中文友好提示
4. **行情引擎**：组合 WS 流接入，快照状态更新，行情页 + 蜡烛图渲染
5. **交易链路**：下单面板（量化/确认）→ POST order → user data stream executionReport 实时刷新挂单与余额 → 撤单
6. **历史与打磨**：myTrades/allOrders 表格、账户估值看板、设置页（testnet 切换、recvWindow、限速参数）、日志落盘
7. **验证收尾**：全量 `cargo build / clippy / test`，编写 README（Testnet API Key 申请与使用说明）

## 说明与风险
- Binance 在部分国家/地区受限，工具提供 base URL 覆盖能力但不负责网络可达性
- MVP 为现货；engine/binance 层按市场抽象，后续加合约（fapi）不需推翻架构
- 软件仅供个人交易辅助，不构成投资建议（README 声明）
